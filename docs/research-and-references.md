# Research and References

## Purpose

Use this file to track research, standards, and existing tools that inform IDLE's design. Add a source only after checking the original publication or official documentation.

## Research areas to investigate

### Visual accessibility and flashing content
- Photosensitive seizure safety guidance and flashing-content standards.
- Web Content Accessibility Guidelines (WCAG), including animation and motion-related guidance.
- Browser support for reduced-motion preferences.
- Research on visual discomfort and temporal visual stimuli.

### Motion and vestibular symptoms
- Research on visually induced dizziness and visually complex motion.
- Accessibility guidance for parallax, scrolling effects, and simulated camera movement.
- Evaluation methods for motion-reduction features.

### Audio processing
- Signal-processing methods for amplitude, RMS, onset, and loudness analysis.
- Platform documentation for authorised audio capture and output control.
- Accessibility guidance for audio alerts and notification management.

### Privacy and security
- Browser-extension permission and security documentation.
- Data minimization and privacy-by-design guidance.
- Secure development and dependency-management practices.

### Existing products and novelty
- Existing operating-system accessibility features.
- Browser extensions that reduce motion or modify page presentation.
- Existing visual comfort and sensory accessibility tools.
- Related research prototypes and patents, where relevant.

## Suggested authoritative starting points

- W3C Web Content Accessibility Guidelines: https://www.w3.org/WAI/standards-guidelines/wcag/
- W3C prefers-reduced-motion media feature overview: https://developer.mozilla.org/en-US/docs/Web/CSS/@media/prefers-reduced-motion
- Chrome Extensions documentation: https://developer.chrome.com/docs/extensions/
- OpenCV documentation: https://docs.opencv.org/
- ONNX Runtime documentation: https://onnxruntime.ai/docs/

These are starting points, not evidence that IDLE is novel or medically effective.

## Reference record template

For each source, record:
- Full title and authors
- Publication date
- DOI or official URL
- Research question
- Relevant findings
- Limitations
- How it informs IDLE
- Licence or reuse conditions, if applicable

## Research discipline

Do not claim that a feature is unique, clinically validated, or proven to prevent symptoms based only on a project description or a single study. Distinguish published evidence, engineering hypotheses, and IDLE's own measured results.
